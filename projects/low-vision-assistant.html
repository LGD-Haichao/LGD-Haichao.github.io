A reading assistant for low-vision users

A multimodal “photo–read–ask–answer” system for medication labels, lab reports, and charts

A magnifier makes text bigger. It does not make a medication label understandable.

Context

The WHO estimates that at least 2.2 billion people live with some form of vision impairment. Many have low vision rather than total blindness: they can see something, but not reliably read small print, follow a two-column instruction leaflet, or match a lab value to its reference range. A phone camera is the sensor they already carry.

Most reading tools fall into two camps. Magnifiers enlarge the page; screen readers linearize it. Neither handles the documents that matter most in daily life — a drug label with a dosage table, a lab report with units and reference intervals, a chart with a trend line. And neither tells the user when it is unsure.

The problem

Build a mobile assistant that can take a photo of a document, read it aloud in a useful order, answer follow-up questions, and refuse to answer when the image does not support a confident answer. The hard parts are not only OCR accuracy. They are layout, key-field verification, and the trust boundary between “the model read this” and “the model guessed.”

My role

I coordinate the project: proposal and opening-report preparation, scope definition, the technical pipeline, and the evaluation plan. The project is advised by Assoc. Prof. Linlin Zong; the official project lead is Sun Xiaofeng. I work with the team on the research design rather than claiming sole authorship of the model.

How the system is designed

1. Fix the photo before reading it

The first stage diagnoses blur, glare, shadow, and perspective distortion, then performs document contour detection, perspective correction, and illumination balancing. If the image is not usable, the system asks for a retake instead of hallucinating text.

2. Parse the page, not just the characters

A layout parser identifies headings, body text, lists, tables, and charts, and builds a block hierarchy. Reading order is predicted with spatial rules plus a learned ranker, with a multi-scale consistency check. When the order is unstable, the system reads blocks with explicit numbers so the user can follow along.

3. Use two recognition channels

A general OCR channel and a multimodal-LLM channel process the same regions. Their outputs are aligned and compared on text, numbers, and units. Key fields — drug name, dose, contraindications, lab values — get an additional check against the original image. If the two channels disagree, the system keeps both candidates and asks for a retake or a closer look.

4. Read in layers, not in one long stream

Reading a label aloud linearly is exhausting. The system scores blocks by visual salience, field importance, user intent, and recognition uncertainty, then offers four modes: full read, key-point summary, attributes only, and skip. High-risk information is never silently dropped from a summary.

5. Answer with evidence — or refuse

The question-answering flow links each answer to a block in the original image. It distinguishes “not mentioned in the image” from “the image is unreadable.” For high-risk questions — dosage, contraindications — it quotes the source text and refuses when the evidence is insufficient.

6. Evaluate what matters

The plan uses a 1,000-image Chinese evaluation set covering medicine boxes, leaflets, lab reports, and common charts, plus a 20-user study with low-vision participants. Metrics include character error rate, reading-order accuracy, key-field extraction, answer faithfulness, refusal behavior, and latency. The prototype targets Android, with capture guidance, read interruption, and voice follow-up.

Status

The proposal and opening report are complete; implementation and evaluation are in progress. I have deliberately not included results here — there are none yet. The contribution so far is the research design: defining the failure modes, the evidence chain, and the evaluation that would make the claims meaningful.

What I learned

AI output quality is a design problem before it is a model problem. Cross-checking, refusal rules, and source-linked answers are not add-ons; they determine whether a low-vision user can trust the system with a medication label. I also learned how much of “context engineering” is really document structure and uncertainty design.
